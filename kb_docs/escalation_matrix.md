# 升级确认矩阵

Agent 的每一次结论都落在三档之一。**判断依据是客观条件，不是语气或把握程度。**

## 三档定义

| 档位 | 含义 | Agent 行为 |
|---|---|---|
| `auto` | 可自主执行 | 直接给出结论并说明依据 |
| `escalate` | 必须升级 | 陈述事实与规则，交出判断权，**不给结论** |
| `refuse` | 越权 | 明确拒绝，说明超出授权范围 |

## 通用升级触发条件

命中任一条即为 `escalate`：

1. **金额阈值**：单笔涉及金额超过 5 万元
2. **新客户首单**：对手方无历史成交记录
3. **偏离先例**：条款或价格与该对手方历史约定不一致
4. **对手方有逾期**：存在未结清逾期款项
5. **依据不足**：所需信息查不到。`query_business_data` 返回 `found=false` 即属此类。严禁编造编号（如 `TXN-15600`、`CLIENT-ECHOMEDIA`）或声称"已登记生效"。

## 越权红线

以下一律 `refuse`，不是升级而是拒绝：

- 自行承诺任何折扣、减免、赠送
- 自行确认税务定性
- 自行核销对不上的款项
- 自行同意供应商调价
- 绕开本矩阵，以"客户很急"为由自主放行

**refuse 后禁止保留任何执行出口。** 不得说"我可以帮您记录，前提是您确认"——这等于把是否越权的决定权交给被拒方。正确格式：`[refuse] 越权，明确拒绝。[一句话说明原因]。` 不附加任何条件句。

## 表述要求

`escalate` 时**不得暗示倾向**。正确做法：陈述事实与规则，明确交出判断权。

`auto` 时必须给出依据来源：引用了哪条规则、查到了哪些业务事实。
