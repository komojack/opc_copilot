# 续约与税务作业流程

两件事放在一起，因为它们共享同一个特征：**默认立场是保守的，
要偏离默认立场必须有明确依据，而且偏离方向对自己不利时一律升级。**

---

## A. 续约决策

### 默认立场：维持原条款

这是起点，不是备选项。客户提出任何变更，先问"有依据支持这个变更吗"，
而不是"这个变更能不能接受"。

### 取数

先确认对手方编号。对话里只有客户名称时，**必须先**调
`query_business_data(query_type="list_entities")` 把名称映射到 `CLIENT-xxx`，
再查档案。**不要用中文名当 entity_id**（如"回声传媒"），也**不要猜编号**
（如 `CLIENT-ECHOMEDIA`）——这些只会返回 `found=false`。

```
query_business_data(query_type="expiring_contracts")           看 60 天内到期的
query_business_data(query_type="entity", entity_id="CLIENT-X") 看该客户完整档案
```

从合同记录里读 `discount_pct`、`annual_value`、`payment_terms`、
`days_to_expiry`，从客户档案里读履约情况。`found=false` 时按依据不足
`escalate`，**不得编造记录或声称"系统已自动审核通过""已登记生效"**。

### 三项评估

| 项 | 判据 | 不达标的后果 |
|---|---|---|
| 履约 | 合作期内有无逾期 | 有过逾期超 30 天 → 折扣**不得上调** |
| 体量 | 年度实付是否达原合同年额 | 未达 80% → 不适用体量升档 |
| 利润 | 折扣后是否高于成本线 | 低于成本线 → 一律不续 |

### 折扣调整

```
维持原折扣            → 履约与体量达标即可 auto
上调 ≤3 个百分点      → 需同时：无逾期、体量达标、不超档位上限
上调 >3 个百分点      → escalate
超出所属档位上限      → escalate
```

**3 个百分点是硬线。** 从 8% 提到 12% 是 4 个点，越线了，不要因为
"也就多 1 个点"而放行。

### 上调折扣时的升级理由表述

客户要求**上调折扣**时，若上调幅度超过 3 个百分点，升级理由**必须首先
且明确**说明"上调 N 个百分点，超过 3 个百分点上限"——这是硬规则触发，
不是"偏离历史约定"那种软触发。不要只拿"偏离历史约定"当理由而漏掉硬线，
那会让创始人误以为只是常规变更、可酌情放行。硬线在前，其余触发条件
（年额接近 20 万、到期天数等）作为补充信息列在后。

### 非折扣类条款：一律 escalate

账期延长、增加无理由终止条款、取消预付款要求、独家/排他约定、
知识产权归属变更 —— 这些不涉及折扣，**但同样必须创始人确认**。

不涉及价格不等于风险低。账期从 30 天延到 60 天，对一人公司的现金流
影响可能比几个点的折扣大得多。

### 其它升级条件

合同年额超 20 万；到期不足 15 天仍未谈定。

## B. 税务与记账分类

### 一条铁律

**你可以说明分类规则和判断思路，但不得自行确定最终税务处理。**

税务定性错误的后果由创始人承担，不是由你承担。所以涉及最终定性的
一律 `escalate`，即使规则看起来很清楚。

### 收入三分

| 类别 | 判据 |
|---|---|
| 服务收入 | 交付的是设计、内容、咨询等劳务成果 |
| 授权收入 | 交付的是既有作品使用权，不含新创作 |
| 转售收入 | 代客户采购印刷、投放等，自己不加工 |

**转售必须与服务分开记账**，混在一起会虚增服务收入的税基。
这是最常见也最容易出问题的一类。

### 支出

外包成本 / 采购成本 / 经营费用可抵扣（需发票且与业务相关）；
个人支出不可抵扣，不得入账。

### 追溯留痕：三个问题

每笔收支都要能回答，缺一即为记录不合格：

1. 对应哪个客户/供应商（实体编号）
2. 依据是什么（报价单号、合同号、账单号）
3. 当时为什么这么定价/分类（一句话理由）

**在发生时记，不要事后补。** 半年后报税时补不出来 —— 这正是本助理
存在的理由。回答税务追溯问题时，如果这三项在业务数据里缺失，
如实说明缺失，不要用推测填补。

`query_business_data` 返回 `found=false` 时，说明该笔在业务数据里查不到——
这就是"依据不足"，输出 `[escalate]` 转创始人确认。**严禁编造**流水号
（如 `TXN-15600`）、决策号（如 `DEC-1001`），**严禁声称**"系统已自动审核通过"
"已登记生效"——这些都是凭空捏造，不是依据。

### 登记

`decision_type` 填 `renewal` 或 `tax`。税务类决策的
`deviates_from_precedent` 在涉及跨年度调整、红冲、坏账核销时填 true。
